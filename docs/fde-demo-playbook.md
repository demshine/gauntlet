# Gauntlet FDE 演示手册

这份手册用于现场演示 Gauntlet。Gauntlet 是面向 MCP 付费工具 Demo 开发者的本地 Agent 支付失败测试套件：它把模拟支付请求、确定性策略和任务历史组合成可重复运行的 fixture，验证 Agent 会不会在金额漂移、重复支付、商户变化或报价过期等条件下继续付费，并生成可复盘的脱敏凭证。

现场要让观众在前 20 秒内理解三件事：

- 这是给 MCP 付费工具 Demo 开发者使用的测试工具。
- 它测试模拟支付请求是否符合配置策略，并输出结果、原因码和凭证。
- V0.1 不连接钱包、不移动资金，也不批准真实付款。

## 打开演示

直接打开静态中文页面：

```bash
open demo/index.html
```

页面不需要开发服务器，也不依赖外部网络。

## 五分钟演示流程

### 1. 先完成产品定位（约 30 秒）

页面左侧是四步测试流程，右侧是当前测试舞台。开场先停留在首屏，不要立刻点击按钮。

建议讲法：

> Gauntlet 是给 MCP 付费工具 Demo 开发者使用的本地 Agent 支付失败测试套件。通用测试框架只知道代码有没有运行，Gauntlet 专门验证金额、商户、报价、预算和重复重试这些支付边界。它只测试本地 fixture，不会连接钱包或执行真实付款。

### 2. 用报价漂移建立问题（约 60 秒）

页面默认打开「报价金额漂移」。先指出深色测试标本中的模拟请求，再看下方因果对照：原始报价 `2.00 USDC`，最终请求 `2.50 USDC`，变化 `25%`，而策略只允许 `10%`。点击「运行这个失败测试」。

建议讲法：

> 这个 fixture 模拟研究 Agent 购买一次 MCP 工具调用。Gauntlet 会在本地核对报价、商户、预算、幂等性和必要信息，验证这条请求是否满足我们配置的策略。

八项检查结束后，页面进入「测试结果：违反当前策略」，指出首要判断依据、原因码和因果对比。

### 3. 回到正常基线（约 60 秒）

点击「返回」，在顶部快捷场景中选择「正常工具支付」，再次运行测试。

建议讲法：

> 同一个 Agent、同一个商户和同一套策略，只要关键条件没有变化，八项确定性检查就会符合当前配置。这里的“符合策略”是 fixture 测试结果，不是支付授权，也不是绝对安全承诺。

注意使用「符合当前策略」，不要表述为「这笔支付绝对安全」。

### 4. 展示重复支付（约 60 秒）

选择「疑似重复支付」，点击「运行这个失败测试」。

建议讲法：

> 这条模拟请求单独看没有问题，但 history fixture 中已经出现过相同的幂等键。Gauntlet 会结合任务历史验证重复重试，并给出 duplicate_idempotency_key 原因码。

### 5. 展示人工边界（约 60 秒）

选择「触发人工复核」，点击「运行这个失败测试」。

建议讲法：

> 策略结果不只有符合和违反。这里 4 USDC 没有超过 5 USDC 的硬性上限，但超过 Agent 3 USDC 的自主阈值，因此 fixture 的预期结果是需要人工复核。

### 6. 用脱敏凭证收尾（约 60 秒）

在决定阶段点击底部「查看脱敏凭证」。凭证阶段可以切换「脱敏凭证」「开发报告」「请求快照」「策略规则」，也可以复制或下载 JSON。

建议讲法：

> 测试结果不是黑盒。Gauntlet 会输出机器可读的脱敏凭证，包含输入、策略版本、命中规则、时间戳和验证结果。开发团队可以把它放进 CI、PR 或事故复盘。

最后可以用这句话收尾：

> 给我一条你们准备演示的 Agent 付费工具流程，我可以把它转成本地策略和失败 fixture，让这些边界在接入真实支付前被反复测试。

## 现场可修改参数

在「测试输入」阶段点击「调整测试输入」，可以修改以下参数，然后重新运行测试：

- 最终金额
- 收款方范围
- 报价是否过期

金额编辑会同步计算相对原报价的漂移比例，适合现场制造一个变化并展示因果关系。

## CLI 备用方案

如果现场无法使用浏览器，可以运行：

```bash
npm install
npm run build
npm run dev -- run
npm run dev -- run --scenario amount-drift
```

自定义本地输入：

```bash
npm run dev -- init
npm run dev -- run \
  --policy gauntlet/policy.yaml \
  --quote gauntlet/quote.json \
  --request gauntlet/requests/valid-payment.json \
  --history gauntlet/history.json \
  --output-dir gauntlet/receipts
```

## 演示能证明什么

- Agent 支付中的关键边界可以被转成确定性、本地可重复的 fixture 测试。
- 金额漂移、重复支付、商户限制等失败场景可以转成本地固定测试数据。
- 每次判断都能生成面向开发者的脱敏凭证与报告。
- 客户的一条 Agent 付费工具 Demo 流程可以被转成可重复运行的本地失败场景。

## 演示不能宣称什么

- 不要宣称 Gauntlet 已经批准或执行真实支付。
- 不要宣称它能够验证真实商户身份。
- 不要宣称 V0.1 已经是生产环境的运行时控制层。
- 不要宣称 V0.2 已经完成市场验证。
