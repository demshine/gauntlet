# Gauntlet FDE 演示手册

这份手册用于现场演示 Gauntlet。目标不是把它包装成已经上线的支付平台，而是在 5 分钟内让客户看懂 Agent 支付的风险、策略边界和可交付凭证。

## 打开演示

直接打开静态中文页面：

```bash
open demo/index.html
```

页面不需要开发服务器，也不依赖外部网络。

## 五分钟演示流程

### 1. 用报价漂移建立问题（约 60 秒）

页面默认打开「报价金额漂移」。先指出中央支付路径和条件变化：原始报价 `2.00 USDC`，最终请求 `2.50 USDC`，变化 `25%`，而策略只允许 `10%`。点击「开始付款前预检」。

建议讲法：

> 研究 Agent 已经准备购买一次 MCP 工具调用，但资金还没有移动。Gauntlet 会先在本地核对报价、商户、预算、幂等性和必要信息，再决定流程是否继续。

八项检查结束后，页面进入「付款请求已拦截」，指出首要判断依据和因果对比。

### 2. 回到正常基线（约 60 秒）

点击「返回」，在顶部快捷场景中选择「正常工具支付」，再次运行预检。

建议讲法：

> 同一个 Agent、同一个商户和同一套策略，只要关键条件没有变化，八项确定性检查就会符合当前配置，流程可以继续。这里的“符合策略”不是支付授权，也不是绝对安全承诺。

注意使用「符合当前策略」，不要表述为「这笔支付绝对安全」。

### 3. 展示重复支付（约 60 秒）

选择「疑似重复支付」，点击「运行预检」。

建议讲法：

> 这笔请求单独看没有问题，但任务历史中已经出现过相同的幂等键。Agent 的重试必须是安全的，而不只是成功的，所以 Gauntlet 会结合历史阻止重复支付。

### 4. 展示人工边界（约 60 秒）

选择「触发人工复核」，点击「运行预检」。

建议讲法：

> 企业控制不只有允许和拒绝。这里 4 USDC 没有超过 5 USDC 的硬性上限，但超过 Agent 3 USDC 的自主支付阈值，因此流程停下来等待人工确认。

### 5. 用脱敏凭证收尾（约 60 秒）

在决定阶段点击底部「查看脱敏凭证」。凭证阶段可以切换「脱敏凭证」「开发报告」「请求快照」「策略规则」，也可以复制或下载 JSON。

建议讲法：

> 决定不是黑盒。Gauntlet 会输出机器可读的脱敏凭证，包含请求、策略版本、命中规则、时间戳和最终决定。开发团队可以把它放进 CI、PR 或事故复盘。

最后可以用这句话收尾：

> 给我一条你们真实的 Agent 支付流程，我可以把它转成本地策略和失败场景，在真实资金移动前反复预检。

## 现场可修改参数

在支付请求阶段点击「调整请求」，可以修改以下参数，然后重新运行预检：

- 最终金额
- 收款方范围
- 报价是否过期

金额编辑会同步计算相对原报价的漂移比例，适合现场制造一个变化并展示因果关系。

## CLI 备用方案

如果现场无法使用浏览器，可以运行：

```bash
npm install
npm run build
npm run dev -- run
npm run dev -- run --scenario amount-drift
```

自定义本地输入：

```bash
npm run dev -- init
npm run dev -- run \
  --policy gauntlet/policy.yaml \
  --quote gauntlet/quote.json \
  --request gauntlet/requests/valid-payment.json \
  --history gauntlet/history.json \
  --output-dir gauntlet/receipts
```

## 演示能证明什么

- Agent 支付可以在继续调用付费工具前执行确定性策略检查。
- 金额漂移、重复支付、商户限制等失败场景可以转成本地固定测试数据。
- 每次判断都能生成面向开发者的脱敏凭证与报告。
- 客户的一条真实支付流程可以被转成可重复运行的本地预检场景。

## 演示不能宣称什么

- 不要宣称 Gauntlet 已经批准或执行真实支付。
- 不要宣称它能够验证真实商户身份。
- 不要宣称 V0.1 已经是生产环境的运行时控制层。
- 不要宣称 V0.2 已经完成市场验证。
